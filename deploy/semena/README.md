# Семена OpenCode

Корпоративный overlay для OpenCode: локальный агент на ПК сотрудника,
индивидуальная авторизация и локальная модель на `10.1.50.101`.

## Почему без OpenClaw

OpenClaw поддерживает OpenCode через ACP, но рассчитан на одного доверенного
оператора на Gateway. Он не является изоляцией корпоративных пользователей.
Для сотрудников OpenCode подключается напрямую к авторизованному модельному
шлюзу; OpenClaw можно позже развернуть отдельно только для администратора.

## Состав

- OpenCode `1.18.15` на Windows сотрудника;
- небольшой проверяемый auth-service: вход через Open WebUI, отзывные ключи и SQLite;
- TLS-терминация и ограничения запросов в nginx;
- Ollama доступна шлюзу по внутреннему адресу;
- одна отзывная модельная учётная запись на сотрудника.

## Проверка

```powershell
py -m unittest discover -s tests -v
```

## Учётные записи

Обычный сотрудник вводит в установщике свой e-mail и пароль Open WebUI.
Установщик по TLS вызывает `/enroll`; auth-service проверяет данные через
Open WebUI и возвращает персональный ключ. Пароль используется только в этом
запросе и не сохраняется. Повторная установка ротирует ключ пользователя.

Аварийные административные команды выполняются на модельном сервере из
`/opt/semena-opencode`:

```sh
./scripts/new_user.sh employee@sibsemena.ru
./scripts/list_users.sh
./scripts/revoke_user.sh employee@sibsemena.ru
```

Ключ показывается только при создании или ротации записи и хранится у
сотрудника в переменной профиля Windows. В базе сохраняется только HMAC-хеш.

Клиентский ZIP опубликован внутренним агентом по адресу
`http://10.1.50.101:3010/downloads/SemenaOpenCodeSetup.zip`. Установщик
запрашивает e-mail и пароль Open WebUI, автоматически получает персональный
ключ, проверяет SHA256 официального OpenCode и создаёт локальный ярлык
`Semena OpenCode`.

Корпоративная установка не использует профиль уже установленного OpenCode:
бинарник, config, data и cache лежат в `%LOCALAPPDATA%\Semena OpenCode`, а
локальное веб-окно слушает отдельный порт `4097`. Официальный архив сначала
скачивается с внутреннего сервера и всегда проверяется по закреплённому SHA256;
GitHub остаётся резервным источником.
